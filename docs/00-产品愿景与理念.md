# 产品愿景与理念

> 本文档记录产品的北极星定位和长期理念，**不是**近期执行范围。
> 与 PRD 的关系：PRD 定义"现在做什么"，本文档定义"为什么做、未来可能成为什么"。
> 本文档中的功能设想不构成开发承诺，主要作用是**指导架构留白的方向**——遇到相关功能需求时，
> 判断标准是"能否用新增表/新增可空字段实现，不碰现有必填约束"（即 OCP 开闭原则），
> 具体实现时机和方式留到真正要做时再讨论。

## 核心洞察

现有任务管理软件普遍"死板"：只有任务内容、时间、简单的周期设定，市面上很多优秀的任务/项目管理理念没有被引入到面向个人的工具里。

现代人需要同时扮演多个角色（项目负责人、团队成员、家庭角色、个体生活者……），核心痛点不是"记不住要做什么"，而是**在有限的空闲时间里，从所有角色、所有领域中，快速锁定当下最该做的事**。这个产品的定位参考了对政治家、企业家、艺术家等身兼多重角色的高负荷人群的观察。

## 产品北极星

不做又一个列表软件，而是做一个**跨领域角色决策引擎**：

- **分类**负责纵向管理——每个人生角色/项目各自独立的任务清单
- **矩阵**负责横向决策——跨越所有分类，在全局范围内锁定当下最优先的任务

两者配合，解决"我该先做哪个角色的哪件事"这个现有工具都没有很好回答的问题。

## 研发文化

这不是一个功能范围封闭的产品。开发过程中如果发现优秀的项目管理、任务管理、生活管理理念，应当有机制去评估、吸纳，持续演化。这也是坚持 OCP 开闭原则的意义所在——架构要为"随时可能加入新理念"留好扩展空间。

## 长期设想（不构成当前开发范围）

以下方向已被确认为"想做"，但都还没有具体设计，仅用于提醒架构不要把路堵死：

- **外部生态集成**：
  - 任务详情页的人物字段与系统通讯录打通（04文档 `task_people.contact_id` 已为此预留结构）
  - 地点字段与地图软件打通（04文档 `task_locations.place_id` 已为此预留结构）
  - 日历双向集成（不只是展示，任务时间与日历互通）
  - 通讯录联系人生日自动生成任务，无需用户手动操作
- **团队/多人协作模式**：公司下派任务能流入个人任务库，与生活任务统一管理
- **与微软等外部任务源对接**：意味着未来任务可能有"本地创建"和"外部同步"两种来源，需要一个可扩展的"任务来源"抽象
- **多产品账号体系**：见《账号与多产品体系文档》

## 子任务的产品本质

子任务**不是独立的任务**，只是对一个任务内容的拆分：只有标题和勾选，没有时间、重要性、RACI、任务关系，不单独出现在矩阵、甘特图、今日里，也只有一层。需要独立的时间、重要性、负责人的事情，应该建成一条独立的任务（必要时用任务关系连起来），而不是子任务。数据层面是独立的子任务表（`task_subtasks`）和勾选表（`task_subtask_checks`），不是 tasks 表自关联。具体规则见《产品需求文档》"子任务"一节。

（此前"子任务是完整的 Task、tasks 表自关联（`parent_task_id`）"的设想已作废。）
