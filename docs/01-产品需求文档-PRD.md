# 产品需求文档（PRD）

## 项目定位

一个内置「时间管理矩阵」的任务管理工具，采用 vibe coding 方式开发。产品北极星与长期理念见《产品愿景与理念文档》。

- **形态**：Web + 原生移动应用（非网页套壳），云同步，支持多设备
- **开发环境**：电脑为主

## 上架优先级

Web → 安卓/iOS（网页端可以最快看到效果，符合 vibe coding 快速验证的节奏）

## 主界面定位（重要澄清）

**主界面是列表，不是矩阵。** 日常高频交互参照 Microsoft To Do 的列表形态：

- 默认视图 = 总览（不选分类）下的未完成任务
- 三个可自由组合的筛选维度：
  - **范围**（左侧菜单上区，单选）：总览 / 收藏（标星任务）；点"总览"清空分类选择
  - **分类**（左侧菜单下区，每个分类一个开关）：一个都不选 = 所有分类；可多选累加（命中其一即显示，逻辑或）
  - **状态**（页面内、添加栏下面一行，单选）：全部 / 未完成 / 已完成 / 已错过，默认未完成
- 添加栏在每个清单页面都有：新任务自动带上当前选中的全部分类（没选分类就不带），在"收藏"里新建的任务自动标星
- 这套结构类比 Outlook 的多邮箱管理方式：既能看总览，也能只选一个分类当作"独立清单"来新建/管理任务，数据层面只是打了对应的分类标签（详见《核心算法与业务逻辑》分类章节）

**时间管理矩阵是一个独立的、可选打开的可视化视图（Graphic）**，不是主界面，用于跨分类快速定位全局优先级，不承担日常任务增删改的职责。

## 功能路线图

### MVP（任务基础）

- 创建 / 编辑 / 删除任务
- 循环任务：是普通任务的一个**开关**（不是独立任务类型），打开后可设置 RRULE 循环规则，关闭后任务变回普通任务；重复规则只提供"每 N 天""每 N 周（选星期几）"；循环产生的历史实例记录嵌在任务的展开面板里查看和修改，独立于开关状态存续（详见算法文档）
- 任务详情页：时间、关联人物、地点、详细描述等字段
- **分类（已从 P2 提前到 MVP）**：多对多关系，数据层面是标签，UI 呈现为"归属"体验；每个分类可设置颜色，用于矩阵可视化中的任务分色标识；分类和组的颜色都可以重复，新建时默认取还没用过的第一个，全都用过就从头开始
- 时间管理矩阵：
  - 横轴（紧迫度）：按截止日期距今天的日历天数自动判档（今天算第 1 天，不看几点几分），用户不手动设置，越靠右越紧急；分"短期"（今天到两周）和"长期"（到半年）两种模式，都是 6 格等宽、中线在正中，矩阵上方的文字胶囊显示当前模式、点击切换，默认短期；矩阵没有外框；紧急与否跟着模式（中线右边三格）
  - 纵轴（重要性）：用户手动选择，0-5共六档（0=未设置，1-5为用户可选档位），越靠上越重要
  - 矩阵无可见网格线；圆点是任务的位置，在所属格子内按 id 固定散布、互不重叠；标签是写在细横线上的标题，用力导向算法排布在圆点的任意一侧，各用一条细线连回圆点，连线互不交叉、不穿过别的标签
  - 任务圆点按所属分类分色（可挂多分类时按切片显示）
  - 与清单共用左侧菜单的范围和分类选择；矩阵没有状态行和添加栏；LOGO 右边的图标按钮切换清单 / 矩阵
  - 矩阵下方的象限列表同样遵守左侧选择，每行可直接勾选完成
  - 所有页面共用标题行：没选分类显示"总览"，选了分类时每个分类显示为一个胶囊（名字 + ✕；名字不能点，只有 ✕ 取消选择，编辑分类只走侧边栏的铅笔）；"收藏"下只显示"收藏"。页面顶部高度固定：不管显示哪些按钮，切换页面时标题和快速添加栏都不上下移动（胶囊放不下时左右滑动）
- 交互通则：任何操作都能在触屏上完成，不依赖鼠标悬停或键盘（键盘快捷方式只是额外路径）；全站没有悬停提示和悬停才出现的图标

- **组（合作组、管理组）与组里的项目**：
  - 组是和个人同级的任务容器，组里是一个个项目；组任务必须属于一个项目，不能在项目之外。类型（合作组 / 管理组 / 教育组）建组时确定、之后不能改；建组时可选合作组或管理组，教育组还没开放。一条任务只属于一个容器、不能移动；组之间什么都不共用；分类只属于个人（个人任务可以有多个分类）
  - 两种组只在身份结构上不同：合作组人人都是组长；管理组分组长、管理员、组员，管理员是项目上的身份，只在被任命的项目里有效
  - 项目有名字、颜色（和分类同一套调色板，可以重复）和工具箱。哪种组、哪些工具开哪些功能集中配置在一处（`packages/core` 的 `GROUP_KIND_CONFIG` / `TOOL_FEATURES`）
  - 侧边栏三区：总览（全部、收藏）、组（可折叠）、分类。组区里每个组下面缩进列出我能看到的项目，每个组可以展开 / 收起；组长在组下面有"新建项目"（表单：名字、颜色、工具箱多选、项目成员——从组里所有人里选，默认全选，可以去掉；组长自动在每个项目里）。每个项目旁边有编辑按钮（组长）：改名字和颜色、发起删除项目；工具箱不能改。在组里点分类回到个人总览并选中这个分类
  - 点组：标题是组名，清单列出我能看到的所有项目的任务；快速添加要先选项目（只列出我能建任务的项目），选了开了任务分配的项目才出现执行人和负责人；有一个项目开了任务分配，状态行就有"待确认"。标题右边是组名单按钮（只在项目里的人没有）
  - 点项目：标题是项目名，清单只列这个项目的任务，快速添加默认就是这个项目；标题右边是项目名单按钮；开了任务分配的项目在最右边有切换责任分配矩阵的按钮。所有页面的标题行和快速添加栏位置一致
  - 组任务只有标题、描述、截止日期和时刻、循环、人物、地点（开了任务分配的项目另有 RACI），不使用重要性、分类和收藏；不出现在总览和矩阵里；组里不显示清单 / 时间管理矩阵切换
  - 名单窗口参照 Google 的共享窗口：组名单（组长：邀请人进组、任命组长、踢出组；每个人能退出组）和项目名单（项目管理员：把小组成员加进项目、用邮箱加人、移出组员、添加和删除只有名字的人；组长还能任命 / 撤销管理员、移出管理员；组长不在可移出之列，也不能退出项目）。任命、撤销、踢出、移出都先弹确认窗口
  - 侧边栏每个组旁边有编辑按钮（和分类的铅笔一样），原地表单：组名和颜色（只有组长能改；颜色显示在侧边栏组名前，用和分类一样的调色板）、我在本组的昵称（每个人都能改）、删除组（只有组长能看到，走投票）
  - 工具箱（建项目时选，可以多选或都不选，建好后不能改）：
    - 任务分配：RACI；建任务必须选执行人和负责人（负责人默认是创建者），不能删到一个都不剩；待确认（状态顺序和角标）；任务通知；责任分配矩阵；只有执行人能标记完成，负责人确认或不通过；只有名字的人
    - 没开任务分配：没有 RACI、不选人；项目成员都能标记完成，完成即确认；没有待确认、任务通知、责任分配矩阵和只有名字的人
    - 任务关系：开始 / 结束两行逻辑、等待、甘特图（见下面"任务关系与甘特图"）
    - 个人分类建分类时也选工具箱，只有"任务关系"，之后不能改
  - 身份：
    - 组长（人数不限，不能被撤销）：自动在每个项目里、不能被移出，在项目里等同管理员；只有组长能建项目、任命和撤销项目管理员、邀请人进组、踢出组、任命新组长（全体组长投票，三天不操作算同意）、删除组和删除项目（全体组长投票，一周不操作算同意）
    - 管理员（项目）：在这个项目里建、改、删任务，设 RACI（开了任务分配），往项目里加人、移出组员，添加和删除只有名字的人（开了任务分配）
    - 组员：开了任务分配时只能做 RACI 允许的事，没开时只能标记完成
    - 合作组人人都是组长，所以在每个项目里都是管理员
    - 项目的任务只有这个项目的成员看得到
  - 往项目里加人：小组成员直接加入，不需要同意；组外的人用邮箱邀请，在通知里同意后加入。只加入了项目的人在侧边栏看到组名和自己的项目，看不到组名单；在合作组的项目里是管理员
  - 移出项目：开了任务分配、他在这个项目里有 R 或 A 时失败，弹窗列出他在这个项目里的 RACI；否则确认窗口列出他的 C 和 I，确认后一并去掉；没开任务分配直接确认。踢出组 = 移出组和他所在的所有项目，R、A 检查覆盖所有项目。组员可以退出项目或退出组（同样的检查）；组长不能退出项目；管理组最后一位组长不能退出组
  - RACI：每个字母不限人数；R、A 必须是项目成员，C、I 也可以是这个项目里只有名字的人；项目成员都能看到每条任务的 RACI。任务详情里写全称：执行人（R）、负责人（A）、顾问（C）、知会（I）
  - 任务行下面的简介行：时间、执行人、负责人（开了任务分配）
  - 完成确认（开了任务分配）：R 标记完成后进入"待确认"，任意一个 A 确认后才算已完成，A 也可以在任务详情里点"不通过"让任务回到未完成；R 和 A 是同一个人时直接算已完成；待确认期间截止时间过了不算已错过；循环任务这一轮不需要 A 确认。状态行是 全部、未完成、待确认、已完成、已错过，"待确认"上的角标是当前待确认的任务数（0 时不显示）
  - 责任分配矩阵：每行一条任务、每列项目名单里的一个人（含只有名字的人），格子里写 R、A、C、I；和清单共用状态行；这一轮只能看，人多时左右滑动
  - 通知只在应用内：账号名和通知铃铛固定在侧边栏左下角，任何时候都不因展开内容而改变位置；有未读时铃铛带小圆点；点铃铛时通知以窗口的形式出现在铃铛上方，没有通知时窗口里显示"没有通知"
    - 入组邀请、项目邀请（同意 / 拒绝）；删除组、删除项目、任命组长的投票（同意 / 不同意）。例如"甲邀请你加入「在道以明」的「项目一」"
    - 任务通知（只在开了任务分配的项目里）写明发生了什么，由操作者、动作、对象（被设的人，没有可省略）、任务、改了哪些内容拼成一句话；对象是自己时说"你"。例如"甲把你设为任务一的执行人（R）""甲完成了任务一""丙退回了任务一""乙修改了任务二的截止时间和负责人（A）"
    - 收件人：设为执行人 → 被设的人、知会；完成 → 负责人、知会；确认 / 退回 / 修改 → 执行人、知会。"修改"包括标题、描述、截止时间、循环、删除，以及 RACI、人物、地点。只发给项目成员，不发给自己；同一种通知处理之前只保留一条，再次修改时合并改动的字段
    - 负责人收到的"完成"只有"确认"和"查看"两个按钮；其他任务通知是 ✕ 和"查看"。"查看"进入任务所在的项目，把这条任务滚动到屏幕中间并在清单里原地展开详情；当前状态行看不到它时切到它所在的状态
  - 删除组 / 删除项目：任何组长都可以发起，发起者算同意；其他组长在通知里选择同意 / 不同意，一个不同意就取消（之后可以重新发起）；一周内没有操作算同意；全部同意后删除（组：连同组里的全部项目和任务；项目：连同项目里的任务）。没有定时任务，任何成员打开 TaskApp 时检查是否超时；只有发起者一位组长时直接删除
  - 暂不做：教育组、在甘特图上拖动或编辑、自动的"外部任务"、跨组关系、组任务进总览和矩阵、在责任分配矩阵里直接改 RACI、循环任务的 A 确认、退出单个账号、Google 选择账号

- **编辑与保存（全局）**：
  - 所有原地编辑（任务详情，包括开始 / 结束两行和 RACI；分类、组、项目的表单；组里的昵称；账号的名字）只在点 ✓ 时保存；单行输入框里按回车也保存。点别处不保存
  - 有没保存的修改时：刷新或关闭页面由浏览器自己提示；在应用里切换页面、组、项目、账号，打开另一个任务，或点别处收起时，弹出确认框：放弃修改，或回去继续编辑
- **RACI 人名**：所有出现 RACI 人名的地方（简介行、详情、快速添加、责任分配矩阵、甘特图）人名都放在等宽的格子里，宽度刚好放下 4 个汉字（按字号），放不下显示省略号
- **部署地区**：环境变量 `NEXT_PUBLIC_REGION`（international / china）。china：登录页不显示 Google 登录；其余不变。可以不用 Vercel，用 Docker 在普通服务器上运行（见《部署说明》）

- **任务关系与甘特图**：
  - 哪里生效：组里开了"任务关系"的项目；个人任务只要挂了至少一个开了"任务关系"的分类。没开的地方保持原样。循环任务不参与：没有这两行逻辑，也不能被选为关系对象
  - 详情里的两行逻辑：
    - 开始：固定日期，或者"于〔某任务〕的〔开始 / 结束〕"
    - 结束：固定日期，或者"于〔某任务〕的〔开始 / 结束〕"，或者"开始后 N 天"
    - 开始和结束各用两行：第一行选条件的类型（日期 / 关系，结束还有开始后），第二行放内容
    - 每一行只能二选一；填了关系的那一行日期由系统算出，用户不能手填。一行可以挂多个关系，取最晚的日期；默认只显示一个条件，旁边的"＋"再加一个。每个关系最后有偏移，默认"当天"，点开是 − / + 步进器（一次一天），也可以直接输入数字，显示为"后 N 天"或"前 N 天"
    - 结束日期就是截止时间：算出来后写入截止时间，矩阵和紧迫度照常使用；快捷添加栏里的时间仍然设定结束（固定日期）
    - 开始和结束是同一天、只有开始或只有结束的任务是里程碑（甘特图上画成菱形）
    - 选关系对象：先选项目（组里）或分类（个人），默认是当前所在的项目或分类，再选任务。组里可以选同一组里、我能看到的、开了任务关系的项目里的任务；个人可以选挂了开有任务关系的分类的个人任务。不能跨组，不能在个人和组之间关联；不允许形成循环（保存时拒绝）
    - 前置任务的日期变了，所有依赖它的任务自动重新计算；开了任务分配的项目里，因此被改动截止时间的任务按现有规则给执行人和知会人发"修改了截止时间"的通知，操作者是改动前置任务的人
  - 等待：清单里状态不变，简介行显示"等待 任务名 开始 / 结束"，等多个时只显示第一个，后面加剩余数量。简介行只显示开始那一行条件的等待；结束那一行的条件只在任务详情里显示。等对方结束看对方是否完成（开了任务分配的项目以负责人确认为准）；等对方开始看对方的开始条件是否满足（固定日期看是否到了那天，关系就逐层往上判断）
  - 浮动时间和关键路径：自动计算；终点是当前甘特图范围（这个项目或这个分类）里所有任务最晚的结束日期；浮动时间画成任务条后面一段淡色的延长，浮动为 0 的任务连成关键路径，醒目标出
  - 甘特图：
    - 入口：项目页面标题行右边的看法切换（清单、责任分配矩阵、甘特图并列；责任分配矩阵仍只在开了任务分配的项目里）；个人只选中一个开了任务关系的分类时出现清单 / 甘特图的切换；组页面没有甘特图
    - 时间轴从左到右是过去到将来，每一天是一条刻度线（每个日期就是一条竖线），刻度可在日、周、月之间切换，两天之间的距离按字号算（em），可以左右滑动；"今天"就是今天那条线
    - 任务条从开始那天的线画到结束那天的线：某天结束的任务和同一天开始的任务落在同一条线上；开始和结束同一天、只有开始、只有结束的任务画成那天线上的菱形
    - 一个任务一行，不合并；按开始日期排序；任务名写在条里，条太短写在条右边；开了任务分配的项目在任务名后面加上执行人；任务条按未完成、待确认、已完成区分
    - 关系画成箭头，从前置指向后续，只画两端都在图上的；两个日期都没有的放在最下面的"未排期"区
    - 只能看：点任务条切回清单，把这条任务滚动到屏幕中间并原地展开；和清单共用状态行

> 提醒功能（定时提醒、提前提醒）已明确排除在当前范围外，暂不开发。

## 时间管理矩阵产品定义

- 矩阵**不是**四个独立标签，而是一个由「紧迫度（X）× 重要性（Y）」构成的连续判定逻辑
- 象限（重要且紧急等）是根据 X、Y 计算结果**派生**出的展示分组，用于象限列表视图筛选，不是任务本身存储的字段；四个象限均为合法区域，包括"不重要且不紧急"
- **唯一不进入矩阵的情况**：重要性为 0 档（未设置）且无截止时间（两者都未处理），这类任务只出现在主列表，不出现在矩阵坐标系中
- 远期任务（日历天数 N 超过 365，即扩展向量）不进入矩阵视图；超出当前模式范围的任务图上不画，但仍在四象限清单里
- 没设截止日期、设了重要性的任务：圆点贴在图的最左边缘
- 已逾期的普通任务放在 6 格右边接出的逾期区（1/4 格宽，不分道、不写任何文字），圆点按重要性竖向定位、标红；满 3 天后从矩阵退场，只在列表"已错过"里可见。循环任务永远不进逾期区
- 分类（多对多标签）与矩阵是正交维度：矩阵默认可查看所有分类的任务，也可在左侧菜单多选分类进行筛选
