# 产品需求文档（PRD）

## 项目定位

一个内置「时间管理矩阵」的任务管理工具，采用 vibe coding 方式开发。产品北极星与长期理念见《产品愿景与理念文档》。

- **形态**：Web + 原生移动应用（非网页套壳），云同步，支持多设备
- **开发环境**：电脑为主

## 上架优先级

Web → 安卓/iOS（网页端可以最快看到效果，符合 vibe coding 快速验证的节奏）

## 主界面定位（重要澄清）

**主界面是列表，不是矩阵。** 日常高频交互参照 Microsoft To Do 的列表形态：

- 默认视图 = 总览（不选分类）下的未完成任务
- 三个可自由组合的筛选维度：
  - **范围**（左侧菜单上区，单选）：总览 / 收藏（标星任务）；点"总览"清空分类选择
  - **分类**（左侧菜单下区，每个分类一个开关）：一个都不选 = 所有分类；可多选累加（命中其一即显示，逻辑或）
  - **状态**（页面内、添加栏下面一行，单选）：全部 / 未完成 / 已完成 / 已错过，默认未完成
- 添加栏在每个清单页面都有：新任务自动带上当前选中的全部分类（没选分类就不带），在"收藏"里新建的任务自动标星
- 这套结构类比 Outlook 的多邮箱管理方式：既能看总览，也能只选一个分类当作"独立清单"来新建/管理任务，数据层面只是打了对应的分类标签（详见《核心算法与业务逻辑》分类章节）

**时间管理矩阵是一个独立的、可选打开的可视化视图（Graphic）**，不是主界面，用于跨分类快速定位全局优先级，不承担日常任务增删改的职责。

## 功能路线图

### MVP（任务基础）

- 创建 / 编辑 / 删除任务
- 循环任务：是普通任务的一个**开关**（不是独立任务类型），打开后可设置 RRULE 循环规则，关闭后任务变回普通任务；重复规则只提供"每 N 天""每 N 周（选星期几）"；循环产生的历史实例记录嵌在任务的展开面板里查看和修改，独立于开关状态存续（详见算法文档）
- 任务详情页：时间、关联人物、地点、详细描述等字段
- **分类（已从 P2 提前到 MVP）**：多对多关系，数据层面是标签，UI 呈现为"归属"体验；每个分类可设置颜色，用于矩阵可视化中的任务分色标识
- 时间管理矩阵：
  - 横轴（紧迫度）：按截止日期距今天的日历天数自动判档（今天算第 1 天，不看几点几分；自然天数标尺，14 格等宽，中线为两周），用户不手动设置，越靠右越紧急
  - 纵轴（重要性）：用户手动选择，0-5共六档（0=未设置，1-5为用户可选档位），越靠上越重要
  - 矩阵无可见网格线，任务散布在所属区间内的自由位置，避免同一坐标下的任务视觉重叠
  - 任务圆点按所属分类分色（可挂多分类时按切片显示）
  - 与清单共用左侧菜单的范围和分类选择；矩阵没有状态行和添加栏；LOGO 右边的图标按钮切换清单 / 矩阵
  - 矩阵下方的象限列表同样遵守左侧选择，每行可直接勾选完成
  - 清单与矩阵共用标题栏：没选分类显示"总览"，选了分类时每个分类显示为一个胶囊（名字 + ✕）；"收藏"下只显示"收藏"

> 提醒功能（定时提醒、提前提醒）已明确排除在当前范围外，暂不开发。

### P2（内测阶段）

- 完整分类管理增强
- 搜索
- 数据备份/导出

## 时间管理矩阵产品定义

- 矩阵**不是**四个独立标签，而是一个由「紧迫度（X）× 重要性（Y）」构成的连续判定逻辑
- 象限（重要且紧急等）是根据 X、Y 计算结果**派生**出的展示分组，用于象限列表视图筛选，不是任务本身存储的字段；四个象限均为合法区域，包括"不重要且不紧急"
- **唯一不进入矩阵的情况**：重要性为 0 档（未设置）且无截止时间（两者都未处理），这类任务只出现在主列表，不出现在矩阵坐标系中
- 远期任务（日历天数 N 超过 365，即扩展向量）不进入矩阵可视化展示
- 已逾期的普通任务放在矩阵最右边的逾期区：分三条道（逾期 0 / 1 / 2 天，越逾期越靠右），标红、不写任何文字；满 3 天后从矩阵退场，只在列表"已错过"里可见。循环任务永远不进逾期区
- 分类（多对多标签）与矩阵是正交维度：矩阵默认可查看所有分类的任务，也可在左侧菜单多选分类进行筛选
