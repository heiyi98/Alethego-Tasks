# 产品需求文档（PRD）

## 项目定位

一个内置「时间管理矩阵」的任务管理工具，采用 vibe coding 方式开发。产品北极星与长期理念见《产品愿景与理念文档》。

- **形态**：Web + 原生移动应用（非网页套壳），云同步，支持多设备
- **开发环境**：电脑为主

## 上架优先级

Web → 安卓/iOS（网页端可以最快看到效果，符合 vibe coding 快速验证的节奏）

## 主界面定位（重要澄清）

**主界面是列表，不是矩阵。** 日常高频交互参照 Microsoft To Do 的列表形态：

- 默认视图 = 全部待办任务（跨所有分类的总览）
- 两个可自由组合的筛选维度：
  - **状态筛选**：待办 / 已错过 / 已完成 / 全部
  - **分类筛选**：不选（总览）/ 单选或多选某些分类（命中其一即显示，逻辑或）
- 这套结构类比 Outlook 的多邮箱管理方式：既能看总览，也能切进单个"分类清单"里新建/管理任务，用户体感是"独立清单"，数据层面只是打了对应的分类标签（详见《核心算法与业务逻辑》分类章节）

**时间管理矩阵是一个独立的、可选打开的可视化视图（Graphic）**，不是主界面，用于跨分类快速定位全局优先级，不承担日常任务增删改的职责。

## 功能路线图

### MVP（任务基础）

- 创建 / 编辑 / 删除任务
- 循环任务：是普通任务的一个**开关**（不是独立任务类型），打开后可设置 RRULE 循环规则，关闭后任务变回普通任务；循环产生的历史实例记录独立于开关状态存续（详见算法文档）
- 任务详情页：时间、关联人物、地点、详细描述等字段
- **分类（已从 P2 提前到 MVP）**：多对多关系，数据层面是标签，UI 呈现为"归属"体验；每个分类可设置颜色，用于矩阵可视化中的任务分色标识
- 时间管理矩阵：
  - 横轴（紧迫度）：由任务截止时间自动计算，用户不手动设置，越靠右越紧急
  - 纵轴（重要性）：用户手动选择，0-5共六档（0=未设置，1-5为用户可选档位），越靠上越重要
  - 矩阵无可见网格线，任务散布在所属区间内的自由位置，避免同一坐标下的任务视觉重叠
  - 任务圆点按所属分类分色（可挂多分类时按切片显示）
  - 支持多选点亮分类进行筛选，命中即显示
  - 按状态/分类筛选的列表视图，复用主界面的筛选逻辑

> 提醒功能（定时提醒、提前提醒）已明确排除在当前范围外，暂不开发。

### P2（内测阶段）

- 子任务（产品本质见《产品愿景与理念文档》）
- 完整分类管理增强
- 搜索
- 数据备份/导出

### P3（内测阶段）

- 拖拽调整任务
- 视觉主题（含深色模式）

> P2、P3 可并行推进（P2 面向功能广度，P3 面向前端打磨）。P2、P3 为内测范围，正式上线在 P3 之后，当前阶段不需要担心数据迁移成本。

## 时间管理矩阵产品定义

- 矩阵**不是**四个独立标签，而是一个由「紧迫度（X）× 重要性（Y）」构成的连续判定逻辑
- 象限（重要且紧急等）是根据 X、Y 计算结果**派生**出的展示分组，用于象限列表视图筛选，不是任务本身存储的字段；四个象限均为合法区域，包括"不重要且不紧急"
- **唯一不进入矩阵的情况**：重要性为 0 档（未设置）且无截止时间（两者都未处理），这类任务只出现在主列表，不出现在矩阵坐标系中
- 远期任务（紧迫度超过基本判定的一年范围，即扩展向量）不进入矩阵可视化展示
- 已逾期任务贴靠矩阵右侧边界展示，标红并标注逾期天数，持续 3 天后从矩阵退场，进入"已错过"状态，仅在列表视图可见
- 分类（多对多标签）与矩阵是正交维度：矩阵默认可查看所有分类的任务，也可通过多选点亮分类进行筛选
