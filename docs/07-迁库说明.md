# 迁库说明：TaskApp 从 Mindo 项目迁到自己的 Supabase 项目

TaskApp 的数据目前放在 Mindo 项目（`wsbskrgrkajnzzgpcfws`）的 `taskapp` schema 里。迁库就是新建一个只属于 TaskApp 的 Supabase 项目，在里面建好全部表和功能，然后把前端指过去，最后把 Mindo 里的 `taskapp` 删掉。**数据不保留**：迁过去之后每个人第一次登录时自动建好自己的用户行，任务、分类、组都从空开始。

登录仍然由 Alethego 项目负责，不受影响（见《身份对接说明》）。

## 需要的文件

| 文件 | 用途 |
|---|---|
| `supabase/migrations/20261007000000_initial_schema.sql` | 初始结构：此前 14 份迁移合并成的一份干净结构，行为与合并前完全一致。之后的改库都是在它后面加的新迁移 |
| `supabase/migrations/*.sql` | 初始结构 + 之后的迁移，按文件名顺序执行 |
| `supabase/scripts/taskapp-full-schema.sql` | 上面全部文件按顺序合并成的一份完整建库脚本（在一个事务里执行，最后通知 Data API 重新读取结构），在没有 `taskapp` 的项目里一次执行就建好全部。由 `node supabase/scripts/build-full-schema.mjs` 生成；单元测试会检查它和迁移是否一致。不含本地测试用的时钟替换 |
| `supabase/scripts/drop-taskapp.sql` | 把 TaskApp 一次删干净（`drop schema taskapp cascade`）。TaskApp 的表、函数、触发器、类型、策略、默认授权都只在 `taskapp` 里，不碰同一项目里其他产品的任何东西。只用于迁库后从 Mindo 删除 TaskApp，以及 2026-10-07 那一次替换测试库 |

## 改库的硬规定

从初始结构（`20261007000000_initial_schema.sql`）起：

- 数据库的任何改动都必须是一份**新的迁移**，在现有结构上修改，**保留现有数据**；已经执行过的迁移文件不再改。
- **不允许清空数据、删库重建**。
- 需要改变现有数据的形状时（拆列、改类型、改取值），迁移里要带上**数据转换**，把现有数据转成新形状。

2026-10-07 用初始结构替换 Mindo 测试库是最后一次清空数据（见下面"用初始结构替换测试库"）。

## 用初始结构替换测试库（2026-10-07，一次性）

TaskApp 现在还在 Mindo 项目（`wsbskrgrkajnzzgpcfws`）的 `taskapp` schema 里。替换步骤：

1. 在 Mindo 的 SQL Editor 里执行 `supabase/scripts/drop-taskapp.sql`（删掉旧的 `taskapp`，测试数据一并删掉）；
2. 接着在同一个 SQL Editor 里执行 `supabase/scripts/taskapp-full-schema.sql` 的全部内容；
3. 用下面"建库"里的查询核对数量（23 / 88 / 41 / 20）；
4. 打开 TaskApp 重新登录：每个人第一次登录时自动建好自己的 `users` 行，任务、分类、组从空开始。

不需要改的：Mindo 对 Alethego 的第三方认证登记（项目级设置，与 schema 无关）、Data API 的 Exposed schemas（`taskapp` 这个名字不变，删除后重建会自动对上）、Vercel 环境变量、Alethego 的 Redirect URLs。第 2 步脚本最后的 `notify pgrst, 'reload schema'` 让 Data API 立即看到新结构；如果前端仍报找不到表或函数，在 SQL Editor 里再执行一次这一句。

## 步骤

### 1. 新建 Supabase 项目

在 Supabase 控制台新建一个项目（例如叫 TaskApp）。记下它的项目地址（`https://<新项目>.supabase.co`）和 anon / publishable key。

### 2. 建库

在新项目的 SQL Editor 里打开 `supabase/scripts/taskapp-full-schema.sql` 的全部内容，执行一次。成功后可以用下面的查询核对：

```sql
select
  (select count(*) from pg_tables where schemaname = 'taskapp') as tables,      -- 23
  (select count(*) from pg_proc p join pg_namespace n on n.oid = p.pronamespace
     where n.nspname = 'taskapp') as functions,                                 -- 88
  (select count(*) from pg_policies where schemaname = 'taskapp') as policies,  -- 41
  (select count(*) from pg_trigger t join pg_class c on c.oid = t.tgrelid
     join pg_namespace n on n.oid = c.relnamespace
     where n.nspname = 'taskapp' and not t.tgisinternal) as triggers;           -- 20
```

（数字对应只有初始结构 `20261007000000_initial_schema.sql` 的库；以后加了迁移会变。）

### 3. 把 taskapp 加进 Exposed schemas

控制台 → Project Settings → Data API（API）→ **Exposed schemas**，加入 `taskapp` 并保存。不加的话前端的所有请求都会报 schema 不存在。

### 4. 登记信任 Alethego 签发的令牌（第三方认证）

新项目要和 Mindo 一样信任 Alethego（`https://ibtwrccctdsqdygjebsp.supabase.co`）签发的 access token，这样带着 Alethego 的令牌请求新项目时，`auth.uid()` 就是用户在 Alethego 的编号，`auth.jwt()->>'email'` 是他的邮箱（入组邀请靠它认人）。

用 Supabase 的管理接口（Management API，需要一个 personal access token）：

1. 先查 Mindo 当时是怎么登记的，照抄同样的值：

   ```bash
   curl -s https://api.supabase.com/v1/projects/wsbskrgrkajnzzgpcfws/config/auth/third-party-auth \
     -H "Authorization: Bearer <personal access token>"
   ```

2. 在新项目上做同样的登记（`oidc_issuer_url` 或 `jwks_url` 用第 1 步查到的值）：

   ```bash
   curl -s -X POST https://api.supabase.com/v1/projects/<新项目>/config/auth/third-party-auth \
     -H "Authorization: Bearer <personal access token>" \
     -H "Content-Type: application/json" \
     -d '{"oidc_issuer_url": "<和 Mindo 相同>"}'
   ```

接口的具体字段以 Supabase 管理接口文档为准。不需要任何签名密钥，TaskApp 也不自己签发令牌。

### 5. 修改 Vercel 环境变量并重新部署

在 Vercel 项目的 Settings → Environment Variables 里（Production 和 Preview 都改）：

| 变量 | 新值 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 新项目地址 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 新项目的 anon / publishable key |

`NEXT_PUBLIC_ALETHEGO_URL`、`NEXT_PUBLIC_ALETHEGO_PUBLISHABLE_KEY` 不变。改完后重新部署（环境变量在构建时写进前端，不重新部署不会生效）。

Alethego 的 Redirect URLs 不用改（TaskApp 的域名没变）。

### 6. 验证

打开 TaskApp，登录，建一条任务、建一个组；在新项目的 Table Editor 里能看到 `taskapp.users`、`taskapp.tasks` 里有对应的行。

### 7. 从 Mindo 删除 TaskApp

确认新项目一切正常后：

1. 在 **Mindo** 项目的 SQL Editor 里执行 `supabase/scripts/drop-taskapp.sql`；
2. Mindo 的 Project Settings → Data API → Exposed schemas 里去掉 `taskapp`。

Mindo 对 Alethego 的第三方认证登记是 Mindo 自己也在用的，**不要删**。

## 以后改库

按上面的硬规定：在 `supabase/migrations` 里按时间顺序加新文件（不改旧文件，不清空数据），在线上项目的 SQL Editor 里执行新文件；然后运行 `node supabase/scripts/build-full-schema.mjs` 重新生成完整建库脚本。
