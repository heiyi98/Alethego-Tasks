# Alethego Tasks

内置「时间管理矩阵」的任务管理工具。产品与技术设计见 [`docs/`](./docs)（00–07）。

## 目录结构

```
packages/core/   领域层：纯 TypeScript，无框架依赖（Web / Mobile 共享）
packages/data/   数据层：仓储接口、Supabase 远程实现、本地存储接口
apps/web/        Next.js：任务列表、快速添加、展开面板新建/编辑、矩阵（直接读写 Supabase）
supabase/        数据库：migrations/ 里是初始结构 20261007000000_initial_schema.sql 和之后的迁移（taskapp schema：users、tasks、categories、task_categories、recurrence_occurrences、
                 task_locations、task_people、groups、group_members、group_invitations、
                 group_deletion_requests / votes、group_leader_requests / votes、projects、project_members、
                 project_invitations、project_deletion_requests / votes、project_contacts、task_assignments、
                 task_notifications、task_relations + RLS）；scripts/ 里是合并好的完整建库脚本和从 Mindo 删除的脚本
                 （迁库见 docs/07-迁库说明.md）
```

### packages/core

| 模块                           | 职责                                                                                                                   |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `urgency/` UrgencyCalculator   | 紧迫度：按日历日 N 判档，短期 / 长期两种模式各 6 格 + 逾期区；超过一年为远期；逾期不封顶                               |
| `quadrant/` QuadrantClassifier | 由（紧迫度 × 重要性 × 模式）派生象限与矩阵展示判定；只接收 `MatrixCandidate`，不感知循环任务                           |
| `recurrence/` RecurrenceEngine | 基于 RRULE 计算下一实例、代表实例（时刻未过的最早未完成实例）、过点即记为未完成（missed）                              |
| `list/`                        | 列表默认排序：截止时间从近到远，无截止时间排最后（循环任务按代表实例）                                                 |
| `matrix/`                      | 矩阵布局：格子 × 重要性行、按 id 固定的格内偏移、象限分组；圆点错开与标签排布（`label-layout`），Web / Mobile 共用     |
| `schedule/`                    | 任务关系：日历日、两行逻辑的日期推算、循环检测、等待、浮动时间和关键路径（数据库里有同样的推算，前端用于预览和甘特图） |
| `representative/`              | 把普通任务 / 循环任务收敛为同一种「一个代表」，再交给矩阵                                                              |
| `time/`                        | 按用户时区计算日历日，不依赖运行环境的系统时区                                                                         |

约定：重要性 0–5（0 = 未设置），3–5 算重要（`IMPORTANT_THRESHOLD`）；紧迫度按日历日判档：
N = (截止日期 − 今天) 的日历天数 + 1（用户时区，今天 N = 1），不看几点几分，日期型与设了时刻的落格相同；
短期模式 6 格 N 的上界为 1 / 2 / 3 / 5 / 7 / 14，长期模式为 3 / 7 / 14 / 30 / 90 / 180（`urgency/tiers.ts` 中的具名常量；
斐波那契数列只是当初选刻度时的参考）；紧急 = 中线右边三格（短期 N ≤ 3，长期 N ≤ 14，逾期一律紧急）。
普通任务截止时刻一过即逾期，逾期天数按日历天计，在矩阵的逾期区（1/4 格宽）里，满 3 天退场
（`OVERDUE_MATRIX_GRACE_DAYS`）；循环任务永不逾期。超过一年（N > 365）的任务不进矩阵视图。

### 数据约定

- **账号**：登录注册由独立的 Alethego 项目负责，数据项目通过第三方认证信任 Alethego 的 access token，
  `auth.uid()` 就是 Alethego 用户编号；数据归属当前登录用户（`owner_id` → `taskapp.users.id`），
  RLS 只对 `authenticated` 开放。详见 [`docs/06-身份对接说明.md`](./docs/06-身份对接说明.md)。
- **快速添加**：只需标题即可创建任务，其余字段之后通过 `update` 补充；空白标题会被拒绝。
- **软删除**：删除任务只写入 `deleted_at`，数据库不开放物理删除；分类关联与循环实例记录保留，可 `restore`。

## 常用命令

需要 Node ≥ 22 与 pnpm 10。

```bash
pnpm install
pnpm test        # 全部单元测试
pnpm typecheck
pnpm build
pnpm dev         # 启动 apps/web
```

本地数据库（需安装 Supabase CLI）：

```bash
supabase start
supabase db reset   # 应用 supabase/migrations
```

业务表全部位于独立的 **`taskapp` schema**（不使用 `public`）。在 Supabase 上部署时，除了执行迁移，
还需要在控制台 **Project Settings → API → Exposed schemas** 中加入 `taskapp`，前端才能访问。

**改库的硬规定**：从初始结构 `supabase/migrations/20261007000000_initial_schema.sql` 起，数据库的任何改动都必须是一份
新的迁移，在现有结构上修改，保留现有数据；不允许清空数据、删库重建。需要改变现有数据的形状时，迁移里要带上数据转换。
改完迁移后运行 `node supabase/scripts/build-full-schema.mjs` 重新生成完整建库脚本（详见 docs/07-迁库说明.md）。

### 运行 Web

```bash
cp apps/web/.env.example apps/web/.env.local   # Alethego 地址与 key、数据项目地址与 key
pnpm dev
```

页面（左侧菜单 + 右侧内容，配色为 Apple 系统色）：

  侧边栏最下面是账号菜单：显示当前账号的名字，点开可切换这台设备上登录过的账号（不需要再输密码）、
  原地修改名字（存 `taskapp.users.display_name`）、添加账号、退出（退出这台设备上的所有账号）。
  登录相关代码集中在 `apps/web/src/auth/`，任务功能只通过 `useCurrentUser()` 取当前用户

- 筛选：内容 = 范围 ∩ 所选分类的并集 ∩ 状态（`buildTaskList`）。选择保存在 URL 查询参数中
  （`/?scope=starred&status=completed&cat=id1,id2`、`/matrix?...`，默认值省略），清单与矩阵共用；
  旧地址（`/list/*`、`/category/*`、`?status=starred`）自动跳转到新写法
  - 左侧菜单上区「范围」单选：总览（默认，点它会清空分类选择）/ 收藏（标星任务）
  - 左侧菜单下区「分类」：每个分类是一个开关，可多选累加，一个都不选 = 所有分类
  - 清单页面内、添加栏下面一行「状态」单选：全部 / 未完成（默认）/ 已完成 / 已错过
  - 菜单底部可新建分类（可选工具箱，只有"任务关系"，之后不能改）；铅笔图标可编辑名称、描述、颜色（颜色可以和别的分类、组、项目相同；新建时默认取还没用过的第一个，全都用过就从头轮换），
    也可删除分类（确认一次；只解除与任务的关联，任务本身保留）
  - 标题行（所有页面共用，高度固定，切换页面时标题和添加栏都不上下移动）：没选分类显示「总览」；
    选了分类时每个分类一个胶囊（名字 + ✕），名字不能点，只有 ✕ 取消选择；放不下时左右滑动。
    「收藏」下永远只显示「收藏」。分类描述只在编辑表单里显示；侧边栏分类旁的铅笔图标一直显示
  - 菜单里的数字：清单模式按页面当前的状态计数，矩阵模式按"未完成"计数；
    范围项在当前所选分类内计数，分类项在当前范围内计数
- LOGO 右边的图标按钮切换清单 / 矩阵；矩阵模式没有添加栏和状态行，只受范围和分类的选择影响
- 添加栏每个清单页面都有：输入栏本身就是标题，下方一行选项（重要性，默认 0；截止日期，默认无；
  时钟图标可选具体到分钟的时刻），点输入栏右端的 ➕ 创建（回车是额外的快捷方式），输入栏左边没有图标、没有占位提示文字；
  输入栏这一行是独立组件，展开详情前后尺寸和图标不变，详情挂在它下方；右侧图标按任务是否已创建决定：
  还没创建是 ➕，已存在、正在编辑是 ✓（立即保存并收起）；
  新任务自动带上当前选中的全部分类，在"收藏"里新建的自动标星。
  当前状态是"已完成""已错过"时新建的任务看不见是正常的，不做自动切换。最右侧的三角展开完整的新建面板
- 截止时间：没选时刻 = 当天最后一刻（过完当天才算已错过）；选了时刻 = 过了那一刻就算已错过。
  列表显示「9月30日 周三 · 还剩2天」，当天显示「今天」，已过期显示「逾期N天」（按日历天，循环任务按当前代表实例）
- 标星：列表行和面板里的星标图标切换（未标星的显示空心星，一直可见），只是书签，不影响矩阵位置、排序或其他规则
- 全站没有鼠标悬停效果（没有悬停提示、悬停加粗、悬停才出现的图标），任何操作都能在触屏上完成；
  图标按钮只有给读屏软件的 aria-label
- 任务面板（新建与编辑共用同一个组件）：描述、截止日期 / 时刻、重要性、分类、重复规则、地点、人物（多个），
  字段以图标为标签（带 aria-label）。同一时间只展开一个面板；手机上为底部抽屉（顶部自带标题行）
  - 列表中点任务名：这一行留在原位展开并让标题进入编辑；点行内其他区域（勾选框、星标除外）只展开；
    展开后字段直接铺在行下方，没有外框（添加栏展开同理）；改动自动保存，没有保存 / 还原按钮
  - 矩阵上点任务：弹出面板（不跳转），面板顶部自带一行可编辑的标题
  - 新建：对勾创建并收起；叉放弃（已填写内容时确认一次）；收起不丢草稿
  - 收起方式：再点三角、点面板外、桌面按 Esc、手机下滑或点背景
  - 删除任务、删除人物、清空描述不弹确认框，之后几秒内的提示条可一键撤销（任务用软删除 + `restore`）
- `/matrix` 时间管理矩阵：
  - 矩阵没有外框；上方单独一行的文字胶囊显示当前模式（「短期」或「长期」），点击切换（默认短期，本机记住上次的选择）
  - X = 紧迫度（越靠右越紧急）：两种模式都是 6 格等宽，按日历日 N 分档，刻度名标在分界线上，中线在 6 格正中、切换时不动；
    短期从左到右 两周、一周、5天、3天（中线）、2天、1天（N > 14 不画）；
    长期从左到右 半年、一季度、一个月、两周（中线）、一周、3天（N > 180 不画）；
    6 格右边接出 1/4 格宽的逾期区（无刻度、无文字）；没设截止日期的任务圆点贴在图的最左边缘
  - 图上只有刻度名、0–5、四个方位字（重要 / 不重要 / 紧急 / 不紧急）和任务标题，没有轴标题、图例或说明文字
  - Y = 重要性：刻度 0–5 标在分界线上，重要性 N 在标 N 那条线上方的一格，中线在刻度 3 上
  - 圆点（分类颜色，多分类按切片）是任务的位置，按 id 固定在所属格子内部、互不重叠；标签没有外框和背景，
    是写在细横线上的标题（最宽 45ch，随字号变化，超出按宽度截断加省略号），用力导向算法排布在圆点的任意一侧，各用一条细线连回圆点；
    连线互不交叉、不穿过别的标签，标签不压圆点；没有随机成分，同样的数据每次排布相同
  - 逾期区：圆点按重要性竖向定位、互不重叠，外加红色外圈；标签红色
  - 下方为按象限分组的列表（按当前模式判定紧急与否；有哪些任务与模式无关），同样遵守左侧选择；
    每行有完成勾选，行为与清单页相同
- 组（和个人同级的任务容器，类型建组时确定：合作组或管理组）与组里的项目：
  - 组是项目的容器，组任务必须属于一个项目（`?group=…&project=…`）；项目有名字、颜色和工具箱（任务分配、任务关系，
    建项目时多选或都不选，之后不能改）。个人分类建分类时也能选工具箱（只有任务关系）
  - 哪种组、哪些工具开哪些功能集中配置在 `packages/core` 的 `GROUP_KIND_CONFIG` / `TOOL_FEATURES`
    （`featuresForProject` / `featuresForGroupPage`）；清单、时间管理矩阵、责任分配矩阵都从同一份数据取任务
    （`apps/web/src/views/` 各自只负责怎么画）
  - 侧边栏三区：总览 / 收藏、组（可折叠；每个组下面缩进列出我能看到的项目，组可以展开 / 收起；组长有"新建项目"）、分类；
    在组里点分类回到个人总览并选中这个分类
  - 组页面：标题是组名，列出我能看到的所有项目的任务；快速添加先选项目，选了开了任务分配的项目才有执行人和负责人；
    项目页面：标题是项目名，只列这个项目的任务，快速添加默认就是这个项目。组任务没有重要性、分类和收藏，
    不进总览和矩阵，组里不显示清单 / 矩阵切换（`/matrix?group=…` 改成组的清单）
  - 身份：组长自动在每个项目里（不能被移出），只有组长能建项目、任命项目管理员、邀请人进组、踢出组、任命组长、
    删除组和项目；管理员只在被任命的项目里管任务和项目名单；合作组人人都是组长。项目的任务只有项目成员看得到；
    组外的人可以只加入某个项目（用邮箱邀请，在通知里同意），只看得到组名和自己的项目
  - 标题右边的按钮：组页面打开组名单（邀请进组、任命组长、踢出、退出组），项目页面打开项目名单（加小组成员、
    用邮箱加人、任命 / 撤销管理员、移出项目、退出项目、只有名字的人），都先确认；侧边栏组旁的铅笔：组名和颜色（组长）、
    我在本组的昵称、删除组；项目旁的铅笔（组长）：项目名和颜色、删除项目
  - 开了任务分配的项目：任务上设定 RACI（执行人、负责人、顾问、知会）；快捷添加栏在时间旁边选执行人和
    负责人（负责人默认是自己，执行人没选时不能创建），执行人和负责人不能删光（数据库也拦住）；
    R 标记完成后待确认，A 确认或退回；状态行是 全部 / 未完成 / 待确认（带数量角标）/ 已完成 / 已错过；
    任务行的简介行显示时间、执行人、负责人；标题行右边切换清单 / 责任分配矩阵；移出项目、踢出、退出时身上有 R 或 A 就不行。
    没开任务分配：项目成员都能标记完成，完成即确认，没有通知
  - 所有任务行的简介行一直存在、高度固定（没有内容时留空），每个任务行一样高
  - 通知只在应用内：账号名和铃铛固定在侧边栏左下角，通知以窗口出现在铃铛上方；有未读时铃铛带小圆点。
    任务通知按"操作者 + 动作 + 对象 + 任务 + 改了哪些"拼成一句话（文案在 `apps/web/src/i18n/`，
    数据库只记结构化信息）；"查看"进入项目、把任务滚动到屏幕中间并在清单里原地展开
  - 删除组 / 删除项目：发起者算同意，一个不同意就取消，一周内没操作算同意（没有定时任务，任何成员打开 TaskApp 时检查），
    全部同意后删除（连同里面的项目、任务）；只有发起者一位组长时直接删除
- 任务关系（开了"任务关系"的项目；个人任务挂了开有"任务关系"的分类）：
  - 详情里有"开始"和"结束"两行：开始是固定日期或"于〔某任务〕的〔开始 / 结束〕"，结束是固定日期、关系或"开始后 N 天"；
    关系可以挂多个（取最晚），每个有偏移（当天 / 后 N 天 / 前 N 天，− / + 步进器或直接输入）；选关系对象时先选项目或分类再选任务；
    算出的结束写进截止时间；不能形成循环、不能跨组、不能在个人和组之间关联，循环任务不参与（数据库也拦住）；
    前置的日期变了，依赖它的任务在数据库里自动重算（开了任务分配时通知执行人和知会"修改了截止时间"）
  - 清单的简介行显示"等待 某任务 开始 / 结束"（多个时加剩余数量）
  - 甘特图（`?view=gantt`）：项目页面标题行右边的看法切换（清单 / 责任分配矩阵 / 甘特图）；个人只选一个开了任务关系的分类时也有；
    日 / 周 / 月刻度、今天的竖线、左右滑动；一个任务一行按开始日期排序，里程碑、未排期、浮动时间（淡色延长）、
    关键路径（红色）、关系箭头；只能看，点任务条回到清单原地展开
- 「重复」开关打开后可设置重复规则（每 N 天 / 每 N 周的周几，可设结束次数或日期与开始时间），
  截止日期与完成状态改由规则和每次实例决定；库里已有的每月 / 每年规则保持原样、照常计算，编辑器只显示原文
- 循环任务的历史嵌在展开面板里（重复规则下方）：最近两次已过去的实例（最新在上），每行日期、星期、时刻和勾选框
  （勾上 = 已完成，已完成的记录沿用现有的「已完成」样式：删除线、变灰；没做的按「已错过」样式显示：日期标红）；右侧向下三角展开到五行高、可滚动看到所有更早的记录。关闭循环后记录保留

循环任务的代表实例 = 时刻还没过的最早未完成实例，时刻一过立刻换成下一次（清单与矩阵一致）；
列表中的勾选框完成的是「当前这一次」实例（不写任务本身的 `completed_at`），勾选后立刻顺延到下一次；
过点未勾选的实例立刻记为未完成，记录的生成在读取任务时顺带完成（`syncOccurrences`）：第一次从开始时间起补，
之后从最新的一条往后记；改规则时已有记录不动、新规则只管以后到点的实例；改开始时间时从新的开始时间补齐缺的记录。

地点 / 人物存放在独立的扩展表中（`task_locations` 一对一、`task_people` 一对多），`tasks` 表不感知它们，
任务面板通过 `TaskDetailAggregator`（`loadTaskDetail` / `saveTaskExtensions`）统一读写。目前只编辑本地自由文本，
表中已预留 `place_id` / `lat` / `lng` 与 `contact_id`，供以后对接地图与通讯录。

### 端到端测试

驱动真实页面读写本地环境（不连真实的 Alethego / 数据项目）：本地数据项目（Postgres + PostgREST，已应用迁移）
与本地 Supabase Auth（模拟 Alethego，邮箱自动确认，JWT 密钥与本地 PostgREST 一致），`.env.local` 指向它们。
每次运行先注册一个新的主测试账号并保存登录状态（`e2e/global-setup.ts`），账号相关用例各自注册账号。
组和项目的用例同时登录多个账号；删除组投票的一周超时、任命组长的三天超时要固定数据库时钟：在 `.env.local` 里配置本地数据库的直连地址
`E2E_DATABASE_URL`（例如 `postgres://postgres@localhost/app?host=/tmp/alethego-pg&port=54329`），全局准备时会执行
`e2e/sql/test-clock.sql`（只用于本地，绝不要在真实项目上执行）；没配置时这条用例跳过：

```bash
pnpm --filter @alethego/web test:e2e
```

表单与格式化等不依赖浏览器的逻辑另有单元测试（`apps/web/src/lib/*.test.ts`，随 `pnpm test` 运行）。
